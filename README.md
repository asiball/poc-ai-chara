# poc-ai-chara

コーディング Agent(Claude Code / Codex / Gemini CLI など)を、ターミナルや一般的なチャット画面ではなく、
**ノベルゲーム風のキャラクター UI から操作するデスクトップクライアント**の PoC です。

> 「AI キャラクターを眺めるアプリ」ではなく、
> 「キャラクターと会話する感覚で、実際のコーディング Agent を使える開発ツール」を目指します。

本リポジトリは現時点で **調査・設計フェーズ**です。実装はまだありません。
判断の根拠は `docs/` 以下にまとめています。

| ドキュメント | 内容 |
|---|---|
| [docs/research.md](docs/research.md) | 既存 OSS・製品・個人事例の調査、比較表、差別化分析 |
| [docs/architecture.md](docs/architecture.md) | Agent/UI 分離、ACP、プロセス構成、状態管理、permission、表情管理 |
| [docs/mvp.md](docs/mvp.md) | MVP の機能、非対象、実装順、受け入れ条件 |
| [docs/adr/](docs/adr/) | ACP 採用、技術選定、最初の Agent、Novel UI / Developer UI 分離の判断記録 |

---

## 1. プロジェクト概要

### 何を作るか

- Claude Code / Codex などの **既存 Agent をそのままバックエンドとして利用**する(再実装しない)
- Agent との接続は **ACP(Agent Client Protocol)** を第一候補にし、Agent を差し替え可能にする
- UI は **ビジュアルノベル(ADV)の文法**で組む
  - キャラクターの立ち絵(PNG)と数枚の表情差分
  - 名前欄、メッセージウィンドウ、テキスト送り
  - Agent の実行状態に応じた表情切り替え(機械的マッピング。LLM による感情判定は使わない)
  - permission 要求は「選択肢」として提示
- 開発ツールとして必要な情報(Markdown、コードブロック、diff、tool call、terminal 出力、エラー)は
  **詳細パネル(Developer Layer)** に分離し、必要なときだけ開く

### 何を作らないか

- Live2D / VRM のような常時アニメーションするアバター(将来の拡張余地は残す)
- LLM に人格を生成させるチャットボット(既存 Agent の出力をそのまま「台詞」として扱う)
- Agent 本体の再実装、独自のツール実行基盤
- MVP 段階での複数 Agent 同時実行、TTS、音声入力

## 2. コンセプト

### 2.1 中心コンセプト: 「人格付与」ではなく「ADV 文法による表現」

調査(docs/research.md)の結果、既存事例は次の 2 軸に分かれました。

| 軸 | 代表例 | 状態 |
|---|---|---|
| A. AI に人格を付けて会話する | RyzaChat:AI、Open-LLM-VTuber、AIRI、SillyTavern | 商用・OSS とも成熟 |
| B. コーディング Agent の状態をキャラクターで可視化する | Codex Pets(公式)、Claude `/buddy`(一時実験)、clawd-on-desk、Copiwaifu、cc-mascot ほか多数 | 飽和 |
| C. キャラクター UI から実際の Agent を操作する(双方向) | avatar-code(静止画)、Clawd Face(ビデオアバター)、CodeWaifu(Codex のみ投入可) | 少数、演出は薄い |
| D. **ADV 文法(名前欄・メッセージウィンドウ・立ち絵差分・テキスト送り・選択肢)で Agent と対話する** | kourai-khryseai(独自 Agent、Ren'Py)のみ | **Claude Code / Codex 直結のものは未確認** |

本プロジェクトは **D** を狙います。
「AI に人格を付ける」ことは目的ではなく、**既存 Agent とのやり取り(発話・思考・ツール実行・承認・結果)を
ノベルゲームの語彙に翻訳して表示する**ことを中心に据えます。

### 2.2 差別化候補の検証結果(要約)

| 候補 | 検証結果 |
|---|---|
| 1. Live2D ではなく軽量な立ち絵・表情差分 | 差別化としては弱い(静止画+差分の事例は既に複数ある)。**参入コストを下げる設計判断**として妥当 |
| 2. ノベルゲーム的な会話 UX | **主要な差別化**。Claude Code / Codex 直結の ADV 文法クライアントは確認できず |
| 3. ACP による Agent 差し替え | 差別化ではない(acp-ui、AionUi、Zed 等が既に実現)。**採用すべき前提技術** |
| 4. 既存 Agent をそのまま利用 | 差別化ではないが正しい判断。再実装しない |
| 5. Agent ごとにキャラクター割り当て | 小さな差別化。Agent-Quest、pets-driven が近い発想を持つが ADV 形式ではない |
| 6. tool call / diff も扱える | 差別化ではない(実用クライアントでは必須要件)。**演出より優先する制約条件** |
| 7. キャラクター表現と実用 UI の両立 | 差別化になり得る。既存は「可視化のみ」か「実用のみ」に二極化 |
| 8. 眺めるのではなく会話して開発する | 2 と同じ。中心コンセプト |
| 9. 人格生成ではなく ADV 文法で表現 | 2 と同じ。中心コンセプト |

結論: **差別化の実体は 2/7/8/9 に集約され、それ以外は前提条件か実装上の選択**です。
「既存 OSS を組み合わせれば済む」とは言えませんが、**接続層(ACP クライアント、プロセス起動)は
既存 OSS を土台にし、新規に書くのは UI 層に限定する**のが妥当です。

## 3. 想定 UX

### 3.1 基本画面(Novel Layer)

```
+--------------------------------------------------------------+
|                                                              |
|                       [立ち絵: thinking]                     |
|                                                              |
|                                                              |
+--------------------------------------------------------------+
| ミオ                                          ● 実行中 (Bash) |
|                                                              |
| 「テストを走らせてみるね。ちょっと待ってて……」              ▼ |
|                                                              |
+--------------------------------------------------------------+
| > メッセージを入力                                    [送信] |
+--------------------------------------------------------------+
```

- **立ち絵**: Agent の状態(idle / thinking / tool_run / done / error …)に応じて PNG を差し替える
- **名前欄**: キャラクター名。Agent 種別(Claude / Codex)はサブラベルで併記
- **メッセージウィンドウ**: Agent の発話テキストをタイプライター表示。段落ごとにページ送り(▼)
- **状態インジケータ**: 実行中のツール種別を短く表示(演出ではなく実用情報)

### 3.2 permission 要求は「選択肢」

```
+--------------------------------------------------------------+
| ミオ                                                          |
| 「src/auth.ts を書き換えたいんだけど、いい?」                |
|                                                              |
|   ▶ 許可する                                                 |
|     このセッションでは常に許可する                           |
|     やめておく                                               |
|                                        [変更内容を見る]      |
+--------------------------------------------------------------+
```

ACP の `session/request_permission` が返す選択肢(allow_once / allow_always / reject_once / reject_always)を
そのままノベルゲームの選択肢として描画します。diff は詳細パネルで確認できます。

### 3.3 完了時は結果を「詳細を見る」で展開(Developer Layer)

```
ミオ
「できたよ。3 ファイル変更して、テストも通ってる!」

[詳細を見る]
  ● 3 files changed        View diff
  ● npm test  → 12 passed  View output
  ● 4 tool calls           View log
```

- **Novel Layer**: 台詞、表情、選択肢。テキスト送りの対象はここだけ
- **Developer Layer**: Markdown 全文、コードブロック、diff、tool call、terminal 出力、エラー、plan。
  サイドパネルまたは全画面で開く。**コードレビューや操作が不便になる場合はこちらを優先**する
- **バックログ**: ノベルゲームの「ログ」に相当。全文 Markdown のトランスクリプトをそのまま置く

### 3.4 台詞と詳細の分離ルール(MVP)

Agent の応答を Markdown ブロック単位で分け、機械的に振り分けます。LLM は使いません。

| ブロック | 表示先 |
|---|---|
| 通常の段落 | Novel Layer(台詞) |
| コードブロック、表、diff、長いリスト | Developer Layer(台詞側には「[コードを見る]」のリンクだけ残す) |
| tool call / terminal 出力 | Developer Layer(台詞側には状態インジケータのみ) |

## 4. MVP

「まず表情差分 3 枚で Claude Code と会話できる」を目標にします。詳細は [docs/mvp.md](docs/mvp.md)。

1. デスクトップアプリ(Windows 優先)を起動する
2. **Claude Code(`@agentclientprotocol/claude-agent-acp`)** に ACP / stdio で接続する
3. 作業ディレクトリを選び、メッセージを入力する
4. Agent の回答をノベルゲーム風 UI に表示する(タイプライター、ページ送り)
5. 実行中は `thinking.png`、完了したら `happy.png`、通常時は `normal.png`
6. tool permission を選択肢 UI から承認 / 拒否する
7. 必要なときだけ diff / tool call 詳細パネルを開く

MVP から外すもの: Live2D、TTS、音声入力、複数 Agent 同時実行、LLM による感情判定、セッション履歴の UI、リモート Agent。

## 5. 将来像

設計上、次を拡張できるようにしておきます(MVP には持ち込みません)。

- 表情差分の追加(confused / warning / error / surprised …)、瞬きなどの軽いアニメーション
- Agent ごとのキャラクター割り当て(Claude → A、Codex → B、Gemini CLI → C)
- 複数 Agent の同時実行と Agent 間クロスレビュー(Claude が実装、Codex がレビュー)
- TTS、音声入力、キャラクターごとの声
- キャラクターテーマ / コミュニティ製キャラクターパックの配布形式
- 背景画像、トランジション演出、セッション履歴、リモート Agent、モバイル UI

## 6. 前提と注意事項

- **サブスクリプション認証の扱いは各サービスの利用条件に依存し、変更され得ます。**
  Anthropic は第三者開発者が自社アプリに claude.ai ログインを提供したり、Pro/Max の資格情報を仲介することを
  公式に不許可としています(docs/research.md 参照)。本プロジェクトはトークンを保存・仲介せず、
  無改変の `claude` バイナリ自身のログインフローに委ねる設計とし、配布時は API キー経路を前提にします。
  個人が自作クライアントを自分のサブスクで使うことの可否は公式に明文化されておらず、未確認です。
- 「Claude Code」の名称を製品名に使うことは Anthropic のブランド規約で不可とされています。
- ACP アダプタ(claude-agent-acp / codex-acp)は Anthropic / OpenAI の公式ではなく、agentclientprotocol
  organization(Zed / JetBrains)が保守しています。破壊的変更に備えてバージョンを固定します。
- キャラクター素材は同梱せず、ユーザーが用意した PNG を読み込む形式にします(素材ライセンスを本体から分離)。
